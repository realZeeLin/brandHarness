设想设计 · DESIGN CONCEPT

品牌智能体工作台：让智能体真正赋能品牌员工

把「消费者智能洞察平台」演示包从「看板 + 回放对话」改造为以 DeepSeek Harness 为运行底座的智能体工作形态：九大模块成为左栏入口，同时以 API / MCP / CLI 形态被上层 harness 调用；中间是专家与员工的工作对话区，右侧沉淀报告、结论卡、证据与技能。福临门为演示案例。

→ 打开工作台　·　DeepSeek Harness（MIT）

一、设计目标

不是再多一个看板，而是把品牌工作的「问题 → 证据 → 判断 → 交付 → 沉淀」变成员工与智能体一起跑的流程。

智能体友好

每个页面能力都是一个有 JSON Schema 的工具，结构化返回、报错可读、读写分开，智能体可直接编排。

员工可用、可改

业务人员用对话交办；分析师在工具台复现、在技能页改文字；数据同事用接口推数——同一套资产。

可信

数字逐一溯源到工具字段，样本不足就拒答，写操作必须人确认，所有动作留痕。

可迁移

技能是文字、工具是标准接口；底座可换（DeepSeek Harness / 企业智能体 / 自有入口），资产归中粮。

二、智能体设计模式：总控编排 + 技能驱动的专家执行 + 闸门 + 回写

综合采用业界成熟的几种模式，并按品牌业务的「可审计」要求加了两道闸门。

① 路由总助手判断问题属于 8 个业务场景中的哪一个，指派专家（Router）
② 加载技能专家读取技能说明（SOP），按步骤列出执行计划（Plan）
③ 调工具调用九大模块工具，取数、取原文、算指标（Tool Use / ReAct）
④ 校验结论卡每个数字重放工具核对；不达门槛拒答（Verifier / Guardrail）
⑤ 交付结论卡、周报、证据包进入右栏，附证据链（Artifacts）
⑥ 人审签发、技能修订、数据入库必须人确认（Human-in-the-loop）
⑦ 回写结论入洞察库；做法沉淀为技能，下一轮更准（Memory / Skill Learning）

多专家协作（Orchestrator–Workers）

年度报告这类复合任务由总助手拆成 6 类决策，分派洞察分析师、产品机会官、品牌追踪官、活动复盘官、GEO 优化官，再由商情简报员汇编。

技能即 SOP（Skills as Text）

技能是带 frontmatter 的 Markdown（与 DeepSeek Harness 的 SKILL.md 兼容）：何时使用、可用工具、步骤、约束、输出。业务能读、能审、能改，修订留版本。

数据可流入（Ingest → Gate → Recompute）

所有数据集都开放批量导入与流式推入接口，入库前过四道筛，入库后算法层缓存失效，下一次工具调用即用上新数据。

三、总体架构：五层，运行层可替换，资产层与底座归中粮

与《建设方案》五层架构一致；本仓库实现了运行层适配、资产层与底座层的可运行版本。

左栏：入口即能力

模块旁的数字是工具数；悬停看到工具名。点专家把任务直接指派给他，点技能打开技能文字，点任务回放该任务。

中栏：过程透明

谁接手、用了哪个技能、计划几步、每步调了什么工具、返回了什么，全部可见；关键动作停在闸门等人决定。

右栏：结果可带走

交付物可导出 Markdown、签发留痕；证据链可复现；技能草稿确认后进入技能库，成为部门资产。

七、员工赋能路径与部门转型

用

品牌 / 业务人员

用对话交办问题，看证据、改措辞、点签发。不用学 BI。

改

品类分析师

在技能页修订 SOP；审核意见回写技能，下一份周报更准。

沉淀

业务专家

把一次成功分析「沉淀为技能」，变成部门可复用资产。

开发

数据 / 数字化同事

在工具台、CLI、MCP 上组合工具，开发新分析；用接口推入新数据源。

转型节奏（与建设方案里程碑对齐）
